# Product Decision Brief

## Brief details

- **Product or capability:** Huy's organized mind: one private product for archiving, finding evidence, inspecting library coverage, and retaining agent lessons. A knowledge base (KB) is the searchable library; a knowledge graph records named things and specified relationships between them. Agent memory means retained lessons and annotations that later sessions can read. An embedding is a list of numbers representing text or an image for similarity search; re-embedding produces new representations from preserved material. These definitions follow the research's distinction between passage search, coverage, and shared lessons. [R1/REPORT.md](../R1/REPORT.md), [R3/REPORT.md](../R3/REPORT.md), [R4/REPORT.md](../R4/REPORT.md)
- **Brief owner:** Huy; prepared by unit P1 for run `kbu-2026-10-07`.
- **Decision owner:** Huy. He names himself and the agent as end users, and his intended change is “a more organized mind.” [Owner intake](../../knowledge-base/data/intake/kbu-2026-10-07/grounded.md), Intent sections, 2026-10-07.
- **Date / version:** 2026-10-10 / version 1, research decision draft.
- **Status:** Draft, ready for Huy's product choice; implementation and promotion are unapproved and unmeasured here. All future behavior and numerical targets below are proposals unless explicitly identified as reported observations.
- **Next review date:** Calendar date not found. Review when M1, M2, and M3 results are available, and again at each release condition. References to those reports are pending evidence requests, not claims that their results were read.

## Decision requested

- **Decision to make:** Choose **KB plus coverage catalog and memory annotations** as the next product shape, with one archive skill and a shared agent interface. Add a small typed graph only after it demonstrates useful, supported answers. A coverage catalog inventories sources and processing status; an annotation is a separate note attached to evidence. This recommendation is an inference from the research, not a measured product outcome. [R3/REPORT.md](../R3/REPORT.md), [R4/REPORT.md](../R4/REPORT.md), [R5/REPORT.md](../R5/REPORT.md)
- **Why now:** Huy expects more courses, books, papers, and repositories; he wants agents to record lessons, label staleness, and use the same mind across harnesses. A harness is the application running an agent and its tools. The existing lesson inventory spans evolution logs, project wikis, and harness memory, rather than a demonstrated shared writer. [Owner intake](../../knowledge-base/data/intake/kbu-2026-10-07/grounded.md), [R4/REPORT.md](../R4/REPORT.md)
- **Options considered:** Search-only KB plus archive skill; KB plus coverage catalog and memory annotations; full typed graph mind with relationships across the library. Repository consolidation is a separate choice: recommend R6's separate repositories with shared records, setup, and interface. [R6/REPORT.md](../R6/REPORT.md)
- **Decision deadline or constraint:** No calendar deadline is supplied. Preserve useful search while learning. Embedding promotion is **pending M1**; image and code scope is **pending M2**; extraction scale is **pending M3**. Each must satisfy the decision rules below before its capability ships. [M1/REPORT.md](../M1/REPORT.md), [M2/REPORT.md](../M2/REPORT.md), [M3/REPORT.md](../M3/REPORT.md)

## Product and strategy context

It cannot establish everything in a model's training or everything Huy personally understands. That interpretation is an inference grounded in the closed-index limits described by R3. An identifier names a record; a source version identifies the exact edition, revision, or repository snapshot used. Indexing makes material searchable. Archiving and indexing must have separate completion states because a downloaded archive does not prove its content is searchable. [R5/REPORT.md](../R5/REPORT.md)
- **Business or organizational outcome:** This is an internal product for two user types, with no external buyer or revenue objective supplied. Proposed value is fewer repeated investigations, more reliable reuse, and clearer decisions about what to acquire or review. Those execution restrictions continue to apply independently of the long-term local-model vision. [Owner intake](../../knowledge-base/data/intake/kbu-2026-10-07/grounded.md), [R1/REPORT.md](../R1/REPORT.md)

A signed link grants temporary access and must not become a citation or distributed asset identifier. Public LitGraph output and cloud skill bundles remain separate distribution scopes; the owner's answer does not authorize public course publication. R6's component separation supports this boundary. ## Specification and scope

- **Primary user journey or story map:** Huy selects material and scope → the archive skill preserves permitted assets → verification accounts for expected members and explicit gaps → ingestion acknowledges searchable records → Huy or an agent searches and reads original evidence → the agent records an attributed lesson or annotation → Huy reviews contested claims and proposed promotions. The catalog displays archived, indexed, and extraction-complete states separately. This proposed journey combines the source and contribution boundaries in R3–R5. [R3/REPORT.md](../R3/REPORT.md), [R4/REPORT.md](../R4/REPORT.md), [R5/REPORT.md](../R5/REPORT.md)
- **Key scenario and expected behavior:** An agent preparing a repository change asks “do I know X?” The answer describes library evidence, source versions, relevant lessons, and unprocessed material. It does not claim to inspect the agent's pretrained knowledge or Huy's understanding. The interaction loop below is the required agent journey. [R3/REPORT.md](../R3/REPORT.md)

1. **Read:** At task start, read the owner/project scope and relevant memory. Separate original sources from agent-generated candidates, verified lessons, contested claims, and retired guidance. Read supporting evidence before relying on a lesson. These lifecycle states come from R4's proposed model. [R4/REPORT.md](../R4/REPORT.md)
2. **Search:** Use ordinary semantic plus keyword search first; semantic search matches meaning, while keyword search matches terms. Keep existing KB reading tools and evidence identifiers usable through the joined interface. Return compact results, then open selected passages rather than loading the entire collection. [R2/REPORT.md](../R2/REPORT.md), [R6/REPORT.md](../R6/REPORT.md)
3. **Ask “do I know X?”:** Resolve ambiguous names, state source scope and snapshot, and inspect the coverage ledger. A snapshot is the fixed collection version being queried; a ledger records completed and incomplete processing. Return supported evidence when present. Missing, failed, skipped, or truncated units require **unknown** for absence. Complete processing with no extracted support means **no indexed evidence in this scope**, followed by source review before calling it a confirmed gap. [R3/REPORT.md](../R3/REPORT.md)
4. **Record a lesson:** After a concrete success, failure, or correction, submit one reusable claim with context, trigger, action, limits, outcome, writer/session identity, time, and evidence references. Mark it agent-generated and candidate until a named review or check supports its scope. Missing evidence remains explicit. [R4/REPORT.md](../R4/REPORT.md)
5. **Annotate and tag:** Attach questions, disagreements, examples, and related-resource tags beside the exact source version. Store a quoted passage and surrounding text with the locator. Semantic similarity may suggest a link; it does not verify a relationship. Tags classify records and do not promote authority. [R4/REPORT.md](../R4/REPORT.md)
6. **Flag stale:** If evidence breaks, a dependency changes, a source fingerprint changes, or review becomes due, append a stale flag with its reason. A content hash is a fingerprint calculated from source bytes. Keep review date, last support, expiry, and usage separate. Ambiguous reattachment leaves an annotation detached for review. [R4/REPORT.md](../R4/REPORT.md)
7. **Recover and hand off:** The shared writer returns record/revision identifiers plus saved and indexed states. Retry a temporary failed write once with the same request key; repeated submission must not duplicate a record. A conflicting revision stops replacement and returns the conflicting records for review. An unavailable writer leaves an explicitly unsent draft; an unavailable graph leaves normal search available. These recovery rules implement R4's proposed write contract and R3's search fallback. [R3/REPORT.md](../R3/REPORT.md), [R4/REPORT.md](../R4/REPORT.md)

Proposed access is one Model Context Protocol (**MCP**) interface, meaning an agent tool interface, plus a command-line fallback using the same writer. Source reads, memory writes, and archive jobs remain distinct operations. During the pilot, cap retrieved source and memory context at **6,000 tokens** per question in every comparison arm. A token is a model's unit of input text. Secondary reads consume the same budget; responses disclose omitted counts and pagination. If the budget prevents an answer, report the limit and request a narrower scope rather than asserting absence. This cap is P1's proposed experimental control, not an existing harness limit. R3's existing internal tools already have response caps, but their MCP wrapping remains work to do. [R3/REPORT.md](../R3/REPORT.md), [R6/REPORT.md](../R6/REPORT.md)

- **In scope:** One archive skill with adapters, meaning source-specific translators, for selected courses, books, papers, and repositories; a common versioned inventory; original/translated/derived labels; source and figure identifiers; processing ledger; shared memory writer and readable Markdown notes; lesson, passage-comment, staleness-flag, and tag/link records; private owner-machine release manifests; optional bounded local typed extraction. Markdown is plain text with heading and link markers. A manifest is a structured list of assets, processing results, and gaps. Image search and expanded code retrieval are **pending M2**. [R3/REPORT.md](../R3/REPORT.md), [R4/REPORT.md](../R4/REPORT.md), [R5/REPORT.md](../R5/REPORT.md), [M2/REPORT.md](../M2/REPORT.md)
- **Out of scope / later:** Audio/video embeddings; bulk transcript mining; automatic standing-rule changes; autonomous declarations of research novelty; library-wide graph replacement; public distribution of private source text; and code execution as part of archiving. Huy prefers images inside PDFs and saved frames for the pilot. Video/audio may remain archive assets, with transcripts and selected still images entering search. [Owner intake](../../knowledge-base/data/intake/kbu-2026-10-07/grounded.md), [R3/REPORT.md](../R3/REPORT.md), [R4/REPORT.md](../R4/REPORT.md), [R5/REPORT.md](../R5/REPORT.md)

## Learning plan

- **Highest-risk assumption:** A bounded catalog and evidence graph can make coverage answers more useful without giving false certainty about omissions. - **Hypothesis:** For Huy and coding agents, if one interface exposes processing completeness, source-linked relationships, and attributed memory, then supported relational/coverage answers improve and lessons survive harness changes, because both users can inspect evidence and omissions. - **Smallest useful test or prototype:** A read-only catalog over a selected source snapshot plus the shared annotation writer. - **Participants or benchmark population and scenario:** Adopt R3's proposed **48 source units**, **12 each** from books, course transcripts, papers, and code, drawn from **2 books, 2 courses, 8 papers, and 2 repositories**. A unit is a section or lesson segment with retained context. This is a proposed sample, not material P1 collected. Huy or a knowledgeable reviewer labels source facts and gaps; no interviews or representative human sample are claimed. [R3/REPORT.md](../R3/REPORT.md)
- **Tasks and neutral prompts, or benchmark task/configuration:** Use **96 questions**, split into **24 lookups, 24 relational questions, 24 coverage questions, and 24 gap-review questions**. Coverage includes **12 known-present** and **12 manually checked no-support** cases. Compare A, B without typed extraction, and B with the bounded typed graph; fix sources, answer model, wording, and context budget. Add **12 incomplete-scope probes** by making a required unit's processing state incomplete in each no-support case; a no-evidence answer must become unknown. Keep neighboring source units together when splitting evaluation to avoid revealing test answers through adjacent sections. [R3/REPORT.md](../R3/REPORT.md)
- **Evidence to collect:** Supported correct answers by question class; false absences; unknown-state correctness; evidence locator/quote validity; false name merges; extraction failures and truncation; requests, input/output tokens, completion times, peak memory; changed and unnecessarily reprocessed units; shared write/read receipts; Huy's review minutes and concrete reuse outcomes. Typed graph expansion additionally requires a positive lower bound in a proposed paired 95% confidence interval for supported relational/coverage-answer improvement, with no demonstrated lookup harm beyond the fixed promotion gate. A paired interval compares answers to the same questions while expressing sampling uncertainty. An interval spanning zero leaves benefit inconclusive. This small pilot cannot establish a rare-error rate for the entire library. [R2/REPORT.md](../R2/REPORT.md), [R3/REPORT.md](../R3/REPORT.md)
