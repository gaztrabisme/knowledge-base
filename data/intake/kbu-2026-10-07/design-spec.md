It preserves learning material, finds original evidence, describes the collection's processing limits, and retains lessons from actual work. It should help Huy and an agent distinguish material that is available, material that was searched, material that was not processed, and a generated interpretation. ## Architecture

Use a joined product interface over components with separate responsibilities. An identifier names a logical record; a revision identifies its exact content. A content hash is a fingerprint computed from bytes. Provenance records origin, transformation and supporting evidence. Every result must identify its source revision, locator and privacy scope. A locator opens a particular page, section, caption cue or code position. Search children are small passages; parents supply their enclosing context. A derivative is a labeled copy produced from preserved source material. This common contract connects existing stores without assuming that their records or vector scores are interchangeable. [R2/REPORT.md](../R2/REPORT.md), [R5/REPORT.md](../R5/REPORT.md), [R6/REPORT.md](../R6/REPORT.md).

```text
Selected book / course / paper / repository
  -> platform adapter: identity, membership, permitted access, explicit gaps
  -> archive core: preserved assets, normalized blocks, figures, manifest
  -> mind registry: source versions, evidence locators, processing ledger
  -> validated handoff -> KB index worker -> staged text/sparse/image indexes
  -> verified source-generation activation -> ordinary search + evidence reader

Preserved source units -> optional extraction worker -> raw responses + checks
  -> optional graph generation -> typed relationship and coverage tools

Every harness -> joined MCP gateway or mindctl CLI
  -> search / catalog / coverage / graph reads -> original evidence -> agent answer
  -> candidate lesson / comment / stale flag / proposed link -> memory writer
  -> durable revision + audit receipt -> readable notes + rebuildable memory index
  -> Huy's review -> recorded verification, rejection or concrete patch approval
```

MCP means Model Context Protocol, the shared agent tool interface. CLI means command-line interface. The diagram is a proposed data flow grounded in [R3/REPORT.md](../R3/REPORT.md), [R4/REPORT.md](../R4/REPORT.md), [R5/REPORT.md](../R5/REPORT.md), and [R6/REPORT.md](../R6/REPORT.md). Loading the gateway must never start archive downloads, graph extraction or model promotion. A missing optional backend returns its availability state and leaves ordinary KB tools usable.

One logical owner exists for each kind of record:

| Record kind | Authoritative owner | Other components' role |
|---|---|---|
| Logical source identity, aliases, active revision, release membership | Mind registry | Adapters propose identities; installers carry read-only snapshots. |
| Original assets, normalized source blocks, faithful derivatives, figure occurrences, archive manifest and verification receipts | Archive core | Search and graph consumers reference their hashes and locators. |
| Processing ledger, expected/actual membership, stage results, active index/graph generation pointers | Mind registry | Workers submit checked stage receipts; they do not declare another stage complete. |
| Parent/child retrieval records, dense and sparse representations, index membership receipts | KB index worker | Gateway reads them; source records remain in the archive. |
| Extraction responses, mentions, canonical entities, resolution history, typed assertions and their evidence | Graph worker | Registry records completion; gateway uses explicit read-only graph connections. |
| Lesson, comment, flag, tag/link, feedback, review decision and immutable revision/audit events | Memory writer | Harnesses and Huy submit requests; local files are views or unsent drafts. |
| Component pins, data-part hashes, supported installation matrix | Release builder | Installer validates and activates the declared set. |

This division is an engineering inference from the boundaries in [R4/REPORT.md](../R4/REPORT.md), [R5/REPORT.md](../R5/REPORT.md), and [R6/REPORT.md](../R6/REPORT.md). It prevents a ZIP archive, a packaged file bundle, from becoming evidence of indexing, or an extracted graph from becoming the owner of source truth. JSON, JavaScript Object Notation, is the structured exchange format. Schema versions define the required fields and meanings. Unknown versions fail visibly; adapters must translate explicitly rather than guess.

Proposed implementation: a small SQLite registry and memory event journal, maintained by one service, alongside the existing Qdrant vector store and DuckDB graph store. SQLite is a file-backed relational database; a transaction groups changes that must commit together. Its documented atomic-commit mechanism supports selecting it for the record, audit event and saved receipt transaction, but the product must still prove recovery on its filesystem. Markdown notes, plain text with headings and links, are regenerated from journal revisions. This choice is a D1 inference resolving R4's atomic receipt requirement and readable-note requirement; it does not adopt SQLite as a replacement vector engine. [R4/REPORT.md](../R4/REPORT.md), [R6/REPORT.md](../R6/REPORT.md), [SQLite atomic commit](https://www.sqlite.org/atomiccommit.html), page date not found, checked 2026-10-10.

A source update has a staged generation, meaning a set of records awaiting activation. Index storage identifiers include payload revision, so staging cannot overwrite the previous visible records. The registry activates the new membership only after required text/image receipts match. Retrieval uses the active membership and rejects inactive generations before ranking; merely discarding stale hits afterward can conceal good candidates. A generation may reuse unchanged records from older producing revisions, and both the selected snapshot and producing revision remain visible. No transaction spans SQLite, files, Qdrant and DuckDB: journaled jobs and activation pointers provide recovery, and reconciliation proves readiness. A failed update leaves the previous generation readable. [R5/REPORT.md](../R5/REPORT.md), [P1/product-brief.md](../P1/product-brief.md).

Each query pins a routing record containing physical collection name, embedding profile and source generation before embedding. A request cannot read a new collection with an old query model. Publish that routing record only after the candidate is ready; compatibility tools follow the same record. Generation eligibility must be expressible in index filters or a separately staged collection before activation; an application-side check after a fixed candidate cutoff is insufficient. This is a D1 implementation requirement derived from R1's same-space constraint and R5's visibility rule. [R1/REPORT.md](../R1/REPORT.md), [R5/REPORT.md](../R5/REPORT.md).

Across machines, source/index releases are read-only snapshots; contributions go to the same authoritative memory writer. The future writer host is an open deployment choice. A disconnected client keeps an outbox of unsent drafts with request keys and reports its last synchronized memory revision. Installing data must never replace the writer journal or discard a local outbox. Source reads disclose the local release; a memory note referring to an uninstalled source returns that condition instead of attaching to a different edition. This is proposed synchronization, not a measured existing feature. [P1/product-brief.md](../P1/product-brief.md), [R4/REPORT.md](../R4/REPORT.md), [R6/REPORT.md](../R6/REPORT.md).

## Storage and search

Keep Qdrant, the current dense plus sparse search engine, as the retrieval store. A dense embedding is a numeric list representing meaning. A sparse representation keeps selected terms and their weights. Retain the FastEmbed BM25 keyword leg, where BM25 ranks term matches, with its current inverse-document-frequency correction, which accounts for how common a term is across the collection. Keep distribution-based score fusion, abbreviated DBSF, which combines the normalized score distributions of the two legs. Keep Ettin-150M, the cross-encoder that reads a query and candidate passage together to reorder candidates. CPU means central processing unit; its speed must be measured on the machine serving queries. This preserves the control while testing measured changes, as recommended by [R1/REPORT.md](../R1/REPORT.md), [R2/REPORT.md](../R2/REPORT.md) and [R6/REPORT.md](../R6/REPORT.md).

The initial control is v10 with Jina v5-text-small at 1,024 dimensions. A dimension is a vector coordinate. Preserve parent/child context: parents up to 1,900 tokenizer units and searchable children capped at 250. A token is the model or chunker's unit of text; their tokenizers can differ. Keep the current 50 dense and 50 sparse candidates, 50 fused candidates, top 10 output, parent deduplication, score floor 4 and minimum-result setting 3 for the unchanged reranker. Those are code settings reported by R2, not tuned recommendations for a new scorer. Fixing the dropped short final group and repeated heading suffixes is separate from an embedding comparison because it changes inputs and identifiers. [R2/REPORT.md](../R2/REPORT.md), [R5/REPORT.md](../R5/REPORT.md).

The candidate is `google/embeddinggemma-2`, pinned initially to R1's checkpoint `914f7f89142e33e77833254d9c9b90c3cef7303b`. Native output has 768 coordinates. Register an explicit model adapter and input conventions; changing the environment variable alone would retain the KB's wrong default dimension and Jina task behavior. Use the SearchQuery prefix for ordinary text questions and Document for passages. CodeRetrieval is a separate code-query experiment, since M2 found no advantage over the generic prefix. Google defines these prefixes in its [prompt configuration](https://huggingface.co/google/embeddinggemma-2/blob/main/config_sentence_transformers.json), repository updated 2026-10-06, file date not found; [R1/REPORT.md](../R1/REPORT.md), [M2/REPORT.md](../M2/REPORT.md).

Matryoshka representation learning means a model was trained to retain useful information in leading coordinates. Start with a 768-coordinate float32 reference, then test 256 coordinates first and 512 as the fallback, renormalizing after truncation. Float32 means 32-bit floating-point numbers. Index and query must share the checkpoint, dimension, prompt role, normalization, runtime-compatible preprocessing and embedding-space identifier. An embedding space names those settings; equal dimensions alone do not align Jina and Gemma. Enforce the published 8,192-token input budget explicitly. Online text workers omit vision and audio encoders; image workers load vision only when indexing selected figures. These model capabilities follow [R1/REPORT.md](../R1/REPORT.md) and the [Google model card](https://huggingface.co/google/embeddinggemma-2), repository updated 2026-10-06, card date not found.

Quantization approximates numbers with fewer bits. Model-weight quantization changes inference; stored-vector quantization changes index search. Test these separately. R1's dynamic int8 model converts selected Linear projection layers and retains other weights at float32; its image variant must exempt the patch input projection. Do not call it an entirely 8-bit model. Start with the measured float32 implementation, then its measured int8 variant, before portable runtime exports. An ONNX, Open Neural Network Exchange, export must preserve prompts, pooling, projection and normalization and demonstrate score parity. Conventional float16 is excluded by Google's precision guidance. None of the workstation measurements proves Mac latency or local quality. [R1/REPORT.md](../R1/REPORT.md), [R2/REPORT.md](../R2/REPORT.md), [Google precision guidance](https://huggingface.co/google/embeddinggemma-2).

For Qdrant, first test scalar int8 search representations with original float-vector rescoring. Rescoring recomputes similarity on preserved originals before neural reranking. Keep compressed vectors and the approximate search graph resident when affordable; test originals and large payloads on disk against cold-read tails. Inspect the installed server version before using any memory-placement syntax. Record deployed graph settings rather than invent defaults. Approximate nearest-neighbor search finds nearby vectors without checking every vector; compare its candidate recall against exact float search separately from labeled relevance. Binary/product compression, aggressive primary compression and another database remain deferred unless measured pressure justifies them. [R2/REPORT.md](../R2/REPORT.md), [Qdrant quantization documentation](https://qdrant.tech/documentation/manage-data/quantization/), page date not found.

The first test sequence is: verified unchanged rerun; batched sparse encoding and 128-point writes versus current 32-point writes; pinned Gemma reference; dimension truncation; model int8; stored scalar compression; placement; reranker runtime; then Ettin-68M with fixed candidates, then rerank depth 30 versus 50. ## Knowledge graph and coverage

Build the catalog and ledger first. For each source version and source unit, store kind, external identity, edition/revision, ordered membership, publication date or `not found`, acquisition time, content hash, privacy, archive state, parse state, index state, extraction profile, expected/attempted/completed units, omitted modalities, truncation, errors and quote checks. A source unit is a section, lesson segment or selected file with enough context to interpret its claims. No generated extraction is needed to record source containment and processing state. A complete selected archive can coexist with an incomplete course or library. [R3/REPORT.md](../R3/REPORT.md), [R5/REPORT.md](../R5/REPORT.md).

The ledger distinguishes missing, locked, failed, skipped, truncated, pending, valid-empty and completed states. Valid-empty means a completed checked extraction returned no relations; it is neither a failed request nor proof that the topic is absent. A coverage certificate is a computed response recording the snapshot, selected units, extraction profile, predicate, counts, omissions and review state. It certifies what processing is accounted for, not perfect extraction recall. This implements R3's closed-world boundary: statements concern the explicitly indexed scope. [R3/REPORT.md](../R3/REPORT.md), [M3/REPORT.md](../M3/REPORT.md).

Use this shared ontology, meaning the allowed record types and relationship meanings. Source records are Book, Course, Lesson, Paper, Repository and File; a Symbol is a defined function or class. Knowledge records are Concept, Method, Problem, Dataset, Metric, Claim and Assumption. EvidenceSpan locates supporting original text or pixels. Keep structural relationships such as CONTAINS, IMPORTS and DEFINES separate from extracted EXPLAINS, APPLIED_TO, USES, ASSUMES, COMPARES_WITH, CONTRADICTS, RECOMMENDS_AGAINST, PREREQUISITE_OF and IMPLEMENTS. Structural code relations come from parsing; behavior claims require source-backed interpretation or recorded execution evidence from another authorized job. A method mentioned in a comment is not proof of implementation. [R3/REPORT.md](../R3/REPORT.md), [R5/REPORT.md](../R5/REPORT.md).

Carry LitGraph's raw responses, mentions, aliases, canonical identities, typed concepts and evidence tools into the optional graph subsystem. DuckDB remains its authoritative graph database; bounded in-memory graphs are derived views. Paper and repository source kinds in its documents table are not magically canonical graph-node types. Extend through versioned schemas without rewriting legacy extraction responses. Each assertion stores subject, predicate (the relationship label), object, conditions, negation, source span, extraction profile, verification tier, applicability interval and review history. Claims with different dataset, version, metric or conditions remain distinct. Legacy paid-model extractions stay labeled legacy; new extraction uses a separate local-only profile. [R3/REPORT.md](../R3/REPORT.md), [R6/REPORT.md](../R6/REPORT.md).

The measured M3 workstation profile is the first repair reference. R3's proposed oMLX alternative remains a separate, unmeasured local-model arm; there is no paid extraction fallback. No oMLX or other model is loaded on this Mac during this run. Preserve invalid raw responses for diagnosis, but quarantine their failed assertions from trusted graph reads. Exact-quote validation and semantic review are separate checks; a fuzzy match must never be returned as an exact quotation. [R3/REPORT.md](../R3/REPORT.md), [M3/REPORT.md](../M3/REPORT.md).

Entity resolution decides whether mentions name the same thing. First match explicit source identifiers and version rules. Then find a limited set of plausible same-type candidates within subject namespaces, compare context, and review ambiguous merges. Do not carry over automatic merging at cosine similarity 0.80 or the 0.70–0.80 adjudication band as authority. Cosine measures vector direction, not identity. Preserve aliases with namespace and context; ambiguous names return alternatives. Stable identifiers survive merge/split decisions through recorded redirects, and resolutions retain their evidence and prior membership. Avoid the current full pairwise similarity matrix as the library grows. [R3/REPORT.md](../R3/REPORT.md).

“Do I know X?” first means “what evidence does this library have for X in this scope?” Resolve X or report ambiguity; search ordinary text; retrieve source-linked introduction, application, implementation or evaluation evidence; show relevant annotated lessons separately. Count distinct works as well as evidence spans, so translations and repeated slides cannot inflate independent support. For any absence claim, inspect every required unit's completion and omitted material. Missing, failed or skipped required material gives **unknown**. A completed scope with no extracted match gives **no indexed evidence in this scope**, followed by original-text review before calling it a confirmed library gap. A positive supported finding can be returned even when broader absence remains unknown. [R3/REPORT.md](../R3/REPORT.md), [P1/product-brief.md](../P1/product-brief.md).

“Where are my gaps?” requires a named requirement set: Huy's list of introductions, implementations, evaluations, prerequisites or relationships needed for a task. Compare this set with supported catalog/graph evidence using an anti-join, which returns required entries with no matching support. Join the processing ledger before interpreting the result. Return not acquired, acquired but not indexed, extraction incomplete, processing complete with no extracted support, or support insufficient for the requested requirement. Each row carries snapshot, scope, nearby evidence, missing units, latest known source date and suggested next action. Similarity links and graph holes propose review work; they do not establish novelty or a gap in Huy's understanding. [R3/REPORT.md](../R3/REPORT.md).

## Memory and annotations

Adopt R4's mixed policy with annotation-only agent permissions by default. Original source bytes, imported references, owner decisions and standing skill rules are read-only. Agents may create candidate lessons, passage comments, stale flags, tags/links and evidence-backed feedback. They may regenerate explicitly replaceable summaries from preserved records. They may propose a source patch, but only Huy can approve its exact before/after change against the named source revision. Approval and application are distinct recorded events; approval for a proposal is not permission to rewrite other material. No source edits or promotions occur in D1. [R4/REPORT.md](../R4/REPORT.md), [P1/product-brief.md](../P1/product-brief.md).

Every contribution has stable ID, immutable revision, kind, owner/project scope, origin, authenticated writer, claimed harness/model, session/run IDs, server creation time, assertion type, supporting evidence IDs and review history. Assertion types distinguish observation, inference and user statement. Missing session/model/evidence fields explicitly say `not found` and leave support unresolved. Keep candidate, verified, contested, superseded and retired status separate from authority, expiry and staleness. Verified means a named check or review supports a claim in its recorded scope. It never means universally true. [R4/REPORT.md](../R4/REPORT.md).

A retraction appends a revision; rollback selects a prior accepted state without erasing history. Choose R6 Option C: keep `knowledge-base`, `agent-workflow` and public `litgraph` separate, joined by common contracts, a gateway and optional setup. Explicit configuration locates prompts, data, logs and components without embedding this Mac's paths. Detect real folders that block managed skill links and stale hook paths; show concrete conflicts rather than silently retaining an old copy. [R6/REPORT.md](../R6/REPORT.md).

Private data releases include owner-authorized course content, original/native captions, reading copies, source/figure blobs, sanitized manifests, catalog/ledger snapshots and matching indexes. Verify exact membership and hashes after installation. Keep mutable memory history and unsent drafts outside replaceable release directories. Never put signed links, cookies or credentials into any part. Public LitGraph keeps code, MIT notices, generic contracts and permitted synthetic examples; full private source texts, memory, databases and model logs stay outside that boundary. A cloud skill must explain its available connector or supplied-evidence route instead of assuming a local symlink exists. Cloud upload does not distribute the private library.
